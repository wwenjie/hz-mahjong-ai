# 麻将 RL 调研：其他模型如何处理"吃碰胡"决策学习

调研时间：2026-10-02 · 触发问题：BC/PPO 模型只学会出牌，学不会吃碰胡（胡率远低于教师）

## 1. Suphx（微软亚研，arXiv:2003.13590，天凤 10 段）

### 模型结构：5 个独立模型 + 1 个规则胡牌模型

| 模型 | 输出 | 备注 |
|---|---|---|
| Discard | 34 类（打哪张） | 最难，**特意收集了更多训练样本** |
| Riichi | 2 分类（是否立直） | |
| Chow（吃） | 2 分类（是否吃） | 输入含"用哪组牌吃" |
| Pong（碰） | 2 分类（是否碰） | 输入含目标牌 |
| Kong（杠） | 2 分类（是否杠） | 输入含目标牌 |
| Win（胡） | **纯规则** | 能胡就胡；唯一例外：最后一局胡完总分仍最低则不胡 |

监督学习精度：出牌 76.7%、立直 85.7%、吃 95.0%、碰 91.9%、杠 94.0%。

**关键设计：**
- 吃/碰/杠是**条件二分类**：输入 = 局面 + 候选副露的具体牌，输出"做/不做"置信度。
  多个候选同时可行动时，取置信度最高者。这比"动作类型多分类"更贴合问题结构。
- **胡牌不学**——规则兜底。验证了我们在评测脚本加"能胡必胡"兜底的方向是对的，
  且可以考虑在部署模型里也永久保留这条规则。
- 出牌是 34 分类最难，Suphx 专门为它收集更多样本——印证单头网络被 discard 样本淹没的问题。

### 训练流程
1. 监督学习（人类高手牌谱，天凤）
2. 自对弈 RL（policy gradient + 重要性采样处理轨迹过期）
   - **全局奖励预测**：训练一个预测器从当前局信息预测整场最终奖励，
     解决"单局输了≠打得差"的信用分配问题
   - **Oracle 引导**：先用全知视角（看到别人手牌和牌山）训练，再用 dropout
     逐步丢弃完美信息（γ 从 1→0），最后退化为普通 agent。γ=0 后学习率降到 1/10 继续训，
     并拒绝重要性权重过大的样本保证稳定
   - **熵正则动态调 α**：近期熵低于目标就加大 α，高于目标就减小
3. 运行时策略适应（pMCPA）：对局中用新观测到的公开信息微调离线策略

### 数据/算力规模（参考）
- RL 每个 agent 150 万局，44 GPU（4 参数服务器 + 40 自对弈 worker）× 2 天
- Suphx 最终 ≈ RL-2 训练 250 万局
- 离线评估：100 万局随机生成对局，采样 80 万 × 1000 次算 stable rank（方差控制）

## 3. 对本项目（nnrl2）的直接推论

| 发现 | 对我们的行动 |
|---|---|
| 分离模型/分离头是标准做法 | v6 已记录全量动作（y_action 6 类 + y_tile），训练用共享主干 + 动作头 + tile 头；若仍学不会吃碰，升级为完全独立的吃/碰/杠二分类头（条件输入候选牌） |
| 胡牌规则化 | 评测脚本兜底保留；考虑部署时也规则化"能胡必胡"，把学习容量让给出牌和副露判断 |
| discard 样本淹没 | v6 数据 pass≈14%、吃碰杠胡≈7%，训练时需要按动作类别加权损失或过采样 |
| 熵正则动态调 α | 检查 PPO 是否有 entropy coef 调度；若无，加上（目标熵 + 近期窗口调节） |
| 模拟器吞吐 | 当前 Python 模拟器 ~0.2 局/s/进程，RL 规模受限；并行分片 + nice 是现阶段务实方案 |
| Oracle 引导 | 中长期可选：obs 已有 god 字段（全知特征），可实现"先全知后丢弃"的课程式训练 |
