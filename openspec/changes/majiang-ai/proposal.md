# Proposal

## Why

公司内「杭州麻将 AI 竞技赛」要求参赛者提交一个能接入官方对战平台、全程自动决策出牌、不得人工干预的 AI 程序。仓库当前除 `openspec/` 脚手架外为空，需要在 **10/8 12:00 提交截止**前从零交付「完整可运行源码 + 使用说明」，并在 10/10 首轮、10/12 决赛圈以多阶段锦标赛形式参赛。

平台规则与常规麻将差异极大，且存在多处只有实测才能确认的规格歧义；同时协议层有若干容易被忽略的陷阱（快照无动作合法性、局间 5 秒假手牌、阶段需重新确认出席、平台中断重赛）。因此本变更先确立可验证的规则内核与协议客户端，再在其上迭代策略。

## What Changes

从零建立一套杭州麻将 AI 参赛程序，分为七块：

1. **规则引擎** —— 牌与手牌表示、胡牌（4 面子 + 将 / 七对）、爆头、财神（白板）百搭、番型倍率连乘、庄闲结算、向听数与有效牌、动作合法性判定。
2. **平台协议客户端** —— 令牌认证、多阶段锦标赛状态机、心跳保活、`/state` 长轮询与快照重建、动作提交与错误码处理、限速退避。
3. **并发对局运行时** —— 活跃场发现、M 场并发调度、决策窗口时限与算力预算、断线恢复、异常兜底。
4. **决策引擎** —— 以「阶段内总得分期望最大化」为目标的出牌 / 响应 / 杠 / 胡 / 弃胡飘决策，含财飘阈值停止与动作链堆叠优先级，并区分稳健与激进模式。
5. **对手风险模型** —— 用公开信息估计对手听牌概率与自摸风险，为财飘阈值与抓打圈时机提供输入；含数据集构造、模型训练、离线评估与保守回退。
6. **自对弈与评测** —— 本地模拟器、批量自对弈统计、与官方番型计算端点对拍、测试房实战与事件流采集复盘。
7. **提交物与答辩** —— 使用说明、源码交付形态、赛前 checklist、三维度答辩材料与现场演示。

## Capabilities

### New Capabilities

- `rule-engine`: 杭州麻将规则内核——胡牌与爆头判定、财神百搭、番型倍率、得分结算、向听数与有效牌、动作合法性
- `platform-client`: 官方平台玩家 API 客户端——令牌与认证、多阶段状态机、心跳保活、长轮询与快照重建、动作提交、限速与错误处理
- `game-runtime`: 多场并发对局运行时——活跃场发现、并发调度、决策窗口时限、断线恢复与异常兜底
- `decision-engine`: 决策策略——出牌 / 碰吃杠 / 胡与弃胡飘的期望值决策，含财飘阈值、动作链优先级与稳健激进模式
- `opponent-risk-model`: 对手风险建模——由公开信息估计对手听牌概率与自摸风险，含数据集构造、模型训练、离线评估与保守回退
- `selfplay-eval`: 自对弈与评测基础设施——本地模拟器、批量统计、官方番型对拍、测试房事件流采集与复盘

### Modified Capabilities

无。本变更在空仓库上引入全新能力。

## Impact

- **新增代码**：规则引擎、协议客户端、运行时、决策引擎、自对弈与评测工具、启动与守护脚本。
- **外部依赖**：官方平台 `https://<SERVER>/`（自签证书）的玩家 API；`GET /portal/api/guide/version`（免认证，用于版本自检）；`POST /portal/api/tools/fan-calc`（免认证，用于番型口径对拍）。
- **凭据**：参赛令牌（scoped）与全局令牌仅经环境变量或启动参数传入，不入仓、不入日志、不硬编码。
- **合规红线**：AI 侧不得持有、读取或推断对手手牌，只使用自身手牌、场上已打出牌与各家副露。
- **时间约束**：10/8 12:00 提交截止；10/10 首轮；10/12 决赛圈；10/15–16 集团终评答辩。
- **运维约束**：比赛期间程序须持续在线（在线判据 = 最近 90 秒内有已认证请求），需进程守护与自动重启。
- **不可写死项**：`BaseScore / M / Rounds / YouCaiBiKao / 三个 timeout` 一律以运行时规则接口返回为准。
