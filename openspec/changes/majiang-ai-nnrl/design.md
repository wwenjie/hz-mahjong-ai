# Design

## Context

- **两条仓**：主仓 `majiang_ai`（A+C，策略/验证/仪器）与独立仓 `majiang_rl`（NN/RL 研究线，对主仓**只读**，由 `src/nnrl/paths.py` 代码强制）。本提案在主仓，只记录与协调；实现落在 `majiang_rl`。
- **自对弈是有偏判据**（`notes/OWNERSHIP.md`）。真机噪声底 ≥5pp（22 小时才能分辨），故**筛选靠配对自对弈、真机只做安全网与最终裁决**。
- **已关闭的三条路**（全部实测同向显著负）：出牌近邻重排、响应局部重排、PIMC 前瞻（`records/ab-search-v3-vs-v3.json`、`probe-pref-pairs.json`、`probe-response.json`）。
- **新证据（本提案基线）**：全局回报预测器 **GO**——小样：r=+0.098，CI [+0.037,+0.151]（`majiang_rl/records/probe-return-predictor.json`）；**放大复核：r=+0.136，CI [+0.058,+0.219]**（n_train=31746/n_valid=10407，按场 bootstrap，`majiang_rl/records/probe-return-predictor-big.json`）。两次 CI 均不含 0，方向一致。
- **合规**：特征只用公开信息 + 本人手牌；决策器不得实现 `observe_state`。
- **截止**：10/8 12:00 提交；10/10 首轮；10/12 决赛圈。

## Goals / Non-Goals

**Goals:**
- 把「下一步研究什么、判据是什么」写成可验收、可迭代的文档（而非散落在对话与笔记里）。
- 把**已看过 / 打算看**的论文与开源麻将 AI 固化成台账（含 arXiv 号与证据等级），供决策与"避免重走"。
- 让每条主张都能追溯到 `majiang_rl` 的可复算产物。
- 提供一个**不占用主仓代码所有权**的协调面（本提案只写 `openspec/**`）。

**Non-Goals:**
- 不改 `src/majiang/**`、`verify/**`、`scripts/**`、`docs/**`（各有其所有人）。
- 不在主仓写实现代码（实现只在 `majiang_rl`）。
- 不承诺"一定涨分"——本提案的价值在于**把不确定性变成可判定的实验**。

## Decisions

1. **残差式（residual）而非整段替换**。M 线整段替换 MLP 名次分 −3.4 ~ −4.3（丢掉启发式结构知识）⇒ 只允许模型在启发式的候选面内重排「出牌」，其余动作（胡/杠/碰/吃/响应）委托启发式。
   备选：端到端策略网——否决，M 线已证伪，且 320 局样本量不足以从零学。
2. **奖励改用「整场名次分」而非「单局得分」**。Suphx 原文：输一小局不代表打错。且本仓主判据本就是低方差的名次分。**由全局回报预测器**（见能力 `return-predictor`）提供代替信号。
   备选：继续用单局得分——否决，是"重尾 + 无归一 + 无分解"的最高方差组合。
3. **评测与主仓同口径**。四座位旋转、按房聚类、`place_points` 名次分、跨种子方向一致性。agent-c 已逐行审计确认两套评测器**同口径**（可直接判读）。
4. **对手池而非单一场地**。文献（Balduzzi 1901.08106 / Czarnecki 2004.09468）与主仓实测都指向"单一场地符号不可信"。
5. **文献只用可核对来源**。`web_search` 在本环境**不可用**，一律走 arXiv API / OpenReview；每条标注【摘要确证】或【推测】。

## Risks / Trade-offs

- [回报预测器信号弱（R²≈1.8%，名次二分类准确率≈52.5%）] → 它**不是**用来直接当策略，而是**筛掉无信息方向**；未达预登记阈值即止损，不硬投。
- [回报预测力随进度衰减] → 放大复核按进度分段：**early r=0.162 / mid r=0.089 / late r=0.097**。开局（信息少、差异未显）反而最好预测，后段噪声抬升。⇒ 若要用于「剩余回报」，需按局数分段建模，勿强求单一全局映射。
- [样本量少 4 个数量级（~320 局 vs Suphx 1.5M 局）] → 只能借**思想**不能借规模；优先做便宜的单变量实验。
- [自对弈正偏移 + 真机噪声底 ≥5pp，小效应不可辨] → 判决一律用**低方差机制量**与**跨种子方向**，不用单场符号。
- [真机时代漂移（CPU 竞争、速率额度）] → 比赛期间机器只跑参赛程序（A 的诊断已确认）。
- [检索缺口：无杭州/国标麻将 RL 论文，无"4人麻将 residual 于强启发式"域内论文] → 已在台账显式标注，属**跨域迁移**。

## Open Questions

- 平台在**决策时**是否暴露当前累计得分/排名？现状：`configure(tournament)` 只注入 `base_score` 与 `you_cai_bi_kao`；`Situation` 无累计字段；`features.extract` 刻意排除。若平台/快照其实提供了，则回报预测器可**大幅增强**（累计领先/落后是名次的主力解释项）。
- ReBeL / CFR 系（如 `Mxplainer` 2506.14246）在本平台是否有可迁移的推理期改进？
- 4 人麻将的非传递性/策略循环在**我们的对手池**里有多强？
