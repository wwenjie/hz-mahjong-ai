# Spec Delta

## Purpose

在完全离线的环境（本地模拟器 + 假 transport）下演练运行时对网络故障、平台故障与时序边界的行为，核心交付是**失败时的表现**，确保正式比赛期间异常可恢复、不丢局、不违规。

## ADDED Requirements

### Requirement: 网络与平台故障演练

演练脚本 SHALL 覆盖：平台地址不可达（连接失败）、平台连续返回 5xx、`stage_crashed` 阶段中断重赛、进程被杀后从快照重建接管。每项演练 MUST 记录观察到的行为与恢复结果，全程 MUST NOT 访问真实比赛平台。

#### Scenario: 连接不可达
- **WHEN** 客户端指向不可达地址
- **THEN** 运行时在可观测的退避策略下重试，不崩溃、不丢本地状态，并在日志中留下可诊断信息

#### Scenario: 连续 5xx
- **WHEN** 假 transport 连续返回 5xx
- **THEN** 运行时按退避重试，达到上限后进入可恢复的错误状态而非静默丢失对局

#### Scenario: 阶段中断重赛
- **WHEN** 收到 `stage_crashed` 信号
- **THEN** 运行时按重赛流程处理，不提交任何动作到已作废的阶段

#### Scenario: 进程重启接管
- **WHEN** 模拟进程被杀后从持久化快照重启
- **THEN** 对局状态从快照恢复，继续参与后续局，不重复提交已提交的动作

### Requirement: 时序边界演练

演练脚本 SHALL 覆盖：局间 `phase="settled"` 停顿期间动作提交被拒（409）、跨局长轮询挂起返回 `{"pending":true}`、同一决策窗口的动作冲突竞态、多场对局同时进入决策窗口。

#### Scenario: settled 期间提交动作
- **WHEN** 在 `phase="settled"` 窗口提交任何动作
- **THEN** 客户端识别 409 语义，不视为致命错误，等待下一阶段而非重试轰炸

#### Scenario: 长轮询 pending
- **WHEN** 跨局间隙长轮询返回 `{"pending":true}`
- **THEN** 客户端继续轮询且不误判为对局结束或掉线

#### Scenario: 动作冲突竞态
- **WHEN** 同一决策窗口出现两个竞争的动作提交
- **THEN** 至多一个动作被接受，客户端正确处理被拒响应且不崩溃

#### Scenario: 多场并发决策
- **WHEN** 多场对局同时处于决策窗口
- **THEN** 各场决策互不干扰，速率限制被遵守（合计不超过平台限速）
