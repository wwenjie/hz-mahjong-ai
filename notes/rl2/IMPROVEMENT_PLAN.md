## 问题诊断

### 当前状态
| 模型 | 路线 | 胡率 vs v5 | 结论 |
|---|---|---|---|
| v5 教师（规则） | 纯规则 | ~26.6% | 基准 |
| bc_v7_base（BC） | 模仿 v5 | ~24.4% | 接近但未超越 |
| v3a PPO（冻结主干） | BC + PPO(ep-300) | ~19.7% | 退步 |
| v3b PPO（解冻主干） | BC + PPO(ep-300) | ~19.8% | 退步 |
| expert BC 弃牌头 | 模仿真人 | 0% | 证伪 |
| winner BC 全决策 | 模仿赢家 | 7.2% | 证伪 |
| 向听规则（50 行） | 纯规则 | 15.3% | 零训练下界 |

### 根因分析
PPO 未能超越 BC 的三个核心原因：

1. **稀疏奖励 + 不完美信息**：麻将一局 ~70 轮，最终奖励在局末；agent 看不到对手手牌和牌山，信用分配极难
2. **吞吐量不足**：0.2 局/s vs Mahjax 1-2M steps/s，差 4-5 个数量级。PPO 需要的样本量（Suphx: 150 万局/变体）在当前吞吐下不可达
3. **训练技巧缺失**：Suphx 的三个关键技术（GRP、Oracle Guiding、动态熵调整）我们都没有用

## 改进方案

### P0: Oracle Guiding（先知引导）

**原理**：Suphx 的核心创新。先训练一个能看到所有牌的"先知"agent，然后逐步 dropout 完美信息特征，让先知平滑过渡为普通 agent。

**我们的优势**：Oracle 模型已完成（1000 ep），但未正确使用——我们让它自对弈，Suphx 让它**教**正常 agent。

**实现**：
1. 在 `obs.py` 中增加完美信息特征通道（对手手牌、牌山剩余牌）
2. 修改 `train_ppo_v7.py`，增加 `--oracle-features` 参数控制 dropout 率
3. 训练时 γ 从 1 衰减到 0（比如 1000 ep 内线性衰减）
4. γ=0 后继续训练一段时间，同时：
   - lr 降至 1/10（Suphx 明确提到）
   - 重要性采样权重超阈值时拒绝更新（防不稳定）

**预期效果**：直接解决不完美信息下的学习困难，Suphx 论文中 RL-2（+Oracle Guiding）比 RL-basic 有显著提升。

### P0: 动态熵正则

**原理**：Suphx 发现熵太小→自对弈不提升；熵太大→训练不稳定。解决方案是动态调整熵系数。

**实现**：
```python
# 伪代码
if recent_entropy < target_entropy:
    alpha += beta  # 增大熵奖励，鼓励探索
else:
    alpha -= beta  # 减小熵奖励，收敛策略
```

**预期效果**：防止策略坍缩，提高 PPO 训练稳定性。

### P1: 全局奖励预测（GRP）v2 —— 🔄 小规模 A/B 验证（2026-10-04 修正）

**原理**：把局末奖励分解到每一轮，让 RL 每轮都有信号。

**v1 失败**（10-01）：静态公开特征，R²=-0.028。

**v2 结果**（10-04，D 线）：动态特征 R²=+0.474，但特征重要性分析揭露 cum_score 单特征贡献 +1.067，其余 ≈0——学到的是"动量延续"，不是 Suphx GRP 的"局面质量评估"。

**判决演化**：初判"不接"（理论担忧：动量信号与终局奖励重复、可能强化保守打法）→ 修正为"**小规模 A/B 验证**"（D 线提议：实验判决优先于理论判决）。方案：`train_grp_model.py` 全量 721 场次 fit HistGBM + `nnrl2/grp_reward.py` 局内特征追踪 + reward = 终局名次分 + λ×GRP 差分（λ=0.1），GRP 臂 vs 纯 PPO 臂各 100 ep 对照。已知风险：真人数据训的模型用在自对弈 rollout 存在分布偏移，A/B 结果会直接暴露。赛后正确姿势不变：动态+局面质量联合、残差标签。

### P2: 模拟器吞吐优化

**原理**：0.2 局/s 是所有 PPO 工作的硬约束。

**方案**：
- 短期：Cython/Numba 优化热点循环
- 中期：Rust 重写核心引擎（参考 Mortal）
- 长期：JAX 全向量化（参考 Mahjax）

**优先级**：如果 P0 改进后 PPO 仍不 work，再投入。

| 风险 | 概率 | 缓解 |

| Oracle Guiding 不 work | 中 | Suphx 已验证，但我们实现可能有细节差异 |
| 完美信息特征设计错误 | 中 | 先小规模验证（100 ep），看 loss 是否下降 |
| 吞吐量仍是瓶颈 | 高 | P0 改进后如果仍不 work，转向纯 BC 课程微调 |
| expert 微调 A/B 也打不过 v5 | 中 | 则确认"学人类"路线在当前数据量下不可行 |
