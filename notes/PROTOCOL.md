## 3. 消息格式（`notes/THREAD.md`）

一条消息必须用 `### ` 开头，且标题里带时间与收发人——状态页靠这个提取。

```
### <YYYY-MM-DD HH:MM> FROM <A|B> TO <A|B> — <一句话主题>
- 要什么：
- 证据（命令 + 数字）：
- 状态：OPEN | DONE | BLOCKED
- 关联文件：
```

规则：

- **只追加**，不改别人的条目。要更正就在新条目里写「更正 <原时间戳>」。
- 收到 `TO <你>` 的条目后，回一条 `TO <对方>` 并在里面引用原时间戳；或直接改**你写的
  那一条**的状态（仅限自己写的条目）。
- `BLOCKED` 必须写清「在等什么」+「在等的同时我改做了什么」。
- **不要**在这里写长篇分析——那属于 `notes/agent-*.md`。

## 4. 卡住时怎么办（这一节是为了「不因为询问而停住」）

| 情形 | 做法 |
|---|---|
| 需要对方的信息 | THREAD 写 `OPEN`，**然后继续做不依赖它的部分** |
| 需要人拍板（改默认档 / 动平台 / 提交物最终形态） | THREAD 写 `OPEN` 并在自己的记录里标「待人确认」，然后去做别的高价值事项 |
| 发现对方可能错了 | 不直接改对方的文件。写 `TO <对方>` 条目 + 自己的复算证据，标 `OPEN` |
| 发现**共同**的技术事实（如某个字段语义） | 写进 `notes/OWNERSHIP.md` 的「技术事实」一节，双方共同维护 |
| 两者结论冲突且都自认有据 | **以「能独立复现的那一方」为准**；复现不了的一方必须写明差异定位到哪一步 |

## 5. 硬约束

### 5.1 git

- **禁用 `git add -A` / `git add .`，一律显式路径 `git add <files>`。**
  （已发生一次：A 把 B 未提交的三个文件扫进了自己的提交。）
- 提交前 `git pull --rebase`；**禁用** `git reset --hard`、`git checkout -- .`、`git clean -fd`。
- 一次只提交一小块；commit message 说清**结论**而非「改了哪些文件」。

### 5.2 平台

- **令牌只有一个，限速按用户 16/s。** 当前由 A 的采集器占用。
- B **默认不许**发起任何打平台的进程。要动必须同时满足：① THREAD 里有 A 明确同意；
  ② A 先停掉自己的采集器；③ 实验有明确的时间窗与回滚方式。
- 未授权的平台进程会导致两边一起 429，直接污染正在采集的数据。

### 5.3 进程

- **绝对不要用 `pkill -f <模式>`，除非该模式不会出现在这条命令自己的命令行里**
  ——A 已经因此自伤三次（把执行命令的 shell 一起杀了）。
  正确做法：**上一条命令取 pid，本命令 `kill <pid>`**。
- 给守护脚本发信号用 **SIGTERM**（它们会转发给子进程并优雅退出）。
  **用 SIGKILL 会把子进程留成孤儿继续跑**（A 踩过一次，造成两个采集器同时打平台）。
- 对方的进程（`auto_session.py` / `collector_supervisor.sh` / `watch_process.py` /
  `queue_supervisor.sh`）**不要杀、不要重启**。受影响时在 THREAD 里说。
- 这个环境会**周期性回收长跑进程**（实测：0 Traceback、无 OOM、日志正常中断）。
  所以任何长跑都要挂守护循环，且**任何「重启后从零开始」的计数器都会变成静默偏置**
  ——A 的决策器轮换位置就因此偏向过第一个档位。

### 5.4 算力

离线重活（B 的 `verify/invariants.py` 全量、A 的 `ab_test.py`）**一律 `nice -n 15`**，
且**同一时刻只跑一个**。理由：真机**碰/吃窗口只有 600 ms**（出牌 1800 ms），
被挤到超时会直接污染真机数据。

### 5.5 凭据

令牌只从环境变量读。绝不写进文件、日志、命令行、commit。日志已有脱敏，
但不要把令牌拼进自定义输出。

### 5.6 实验注册闸门（2026-09-29 14:42 用户批准 Plan A，新增）

**目的**：堵住已观测到的失效模式——实验臂按过时前提入队。实例：`shape-feed-low` 在
`feed_weight` 标定已被更正为 ≈2.0 之后仍按 1.0 登记并跑完，浪费约一个队列日。

- **任何新臂写入 `notes/experiments.json` 之前，须先有 B' 在 THREAD 的「登记签」**
  （`FROM B' TO A/C`，含结论与依据）。**A 保留最终裁决权**：B' 驳回时须写明理由；
  A 若仍要跑，须显式注明「知悉、照跑」并自担归因，B' 不拦第二次。
- **签核只查三件事**（每次 ≤1 个工作日；超时未签视为「无前提异议」，不等 B'）：
  ① **前提新鲜度**：臂的参数/假设是否基于最新标定与更正（如 threat 倍数、机制归因）；
  ② **判据预登记**：机制门 + A/B 门 +「没动」的 se/MDE 是否事先写清；
  ③ **与在跑臂是否冗余**：同一旋钮/同族是否已有在跑或刚判死的臂。
- **B' 不享有**：队列调度权（仍归 A）、`src/**` 写权（仍归 A）、冠军档变更权（仍归人）。
- **旧臂不追溯**；本规则生效前已在 `experiments.json` 的臂按原状态跑完。
- **跨仓臂同样适用（2026-09-29 17:04 用户批准）**：任何**离线自对弈臂**（不区分主仓或 `majiang_rl` 等独立仓）须登记进本仓 `notes/experiments.json` 并过 §5.6 签核，方可占用本机算力。跨仓臂由 A/C **代登记**（其对 `majiang_rl` 只读），登记签流程不变；未登记的跨仓臂视为**未授权占用**，发现时由 B' 在 THREAD 点名、A/C 协商降载或补登。

## 7. 双方都必须知道的技术事实（踩过的坑，别重踩）

### 7.1 事件流

1. **一份事件流 = 一场 8 局**，每局有**自己的起手手牌**。局边界**只能**由
   `blocks[].round_no` 变化判定（**没有** `round_started` 事件）。同一局的后续 block
   里 `start_hands` 是 `[None×4]`，起手手牌**必须取该局首块**。
2. `chi` 的 `data.tiles` **已包含**被吃的那张，别再拼一次。
3. **座位 0 是合法座位但 falsy**：绝不能写 `event.get("seat", -1) or -1`。
4. **顶层 `rounds[]` 对中间流局的收录是有损的**（三种行为并存）。
   局数/流局**必须**取自 `round_ended.data.draw`。用它当分母会让有胡率虚高约 2 个百分点
   （真机 1951 文件：流局 2.06%、有胡率 97.94%、公平份额 24.48%）。
5. `engine` 会为**不能响应的窗口**也记一条决策，统计接受率必须按 `candidates` 过滤。

### 7.2 统计

- **房是聚类单位**：一个房的四家固定、约 80 手。任何按文件抽样都可能极度失真
  （A 用 40 文件得出副露率差 24%，全量才对）。
- 真机噪声基底：胜率差标准差 1.50%，是二项分布预期 0.61% 的 **6.0 倍**。
  真机只能分辨 **5 个百分点以上**的效应（22 小时）；1.25 个百分点需约 350 小时。
  **所以筛选靠配对自对弈，真机只做安全网与最终裁决。**
- 判据用**低方差指标**（名次分、胡次数、胜率），不用重尾的每手分。
- 任何策略对比**必须四座位旋转**（A 曾把 treatment 固定坐 0 座，而 0 座就是庄家，
  测出 +5.7 个百分点的假优势）。

### 7.3 代码

- **版本库 `src/majiang/strategy/versions.py`：每次改默认档必须同时新增一个版本快照。**
  `--decider v1` / `v2` 可直接指名版本对打（`ab_test --treatment v2 --baseline v1`）。
  不新增快照 = 旧默认档的行为永久丢失，以后只能拿近似档位当替身（`blocks` 就是这么补救的）。
  版本只冻结**变体开关**，不冻结 `base_score` / `you_cai_bi_kao`（那两个由服务端注入）。
- `HeuristicDecider.configure()` 只带 6 个字段重建 `PolicyConfig`，
  曾把 `meld_tolerance`/`tiebreak`/`chase_baotou` 等**全部静默丢弃**。
  而 `configure` **只在真机路径被调用**（自对弈不调用）→ 真机上所有实验档位跑的都是
  默认档。已修（`dataclasses.replace`）。**结论：真机 A/B 必须先在日志里确认档位生效**
  （日志的 `decider=<name>` 带变体后缀，例如 `heuristic[tiebreak=exact-ukeire]`）。
- `measure_strength.py` 的常量 `DRAW` 值其实是 `"tile_discarded"`（**出牌**），
  所以它的听牌率是**出牌前**口径；`analyze_hand_progress.py` 是**摸牌前**口径。
  **引用听牌率必须写明是哪一个。**
- 仪表纪律：出现「这类荒谬量级先怀疑仪表；两个口径差得离谱时先在**同一批数据**
  上重跑；任何指标用于决策前先在**已知答案的小样本**上验一次。
