## 0. 一句话定义

把出牌评分从「启发式 `total = −10·向听 + 形质 − 3·喂牌 − 财神罚`」换成
**「打完这张牌后，本局期望得分」的显式估计**，让所有候选在**同一量纲（分）**上可比：

```
score(tile) = E[本局得分 | 打出 tile 后] − 打出 tile 的即时风险
```

现状 `total` 的两处实测硬伤：① **量纲不可比**（向听项 −10~−80、喂牌项 0~7.7、形质项 <1——我 14:05：同向听组内 total 极差 **97.25% 来自喂牌项**、形质贡献均值仅 **0.026**）；② **并列靠隐式次序**（59.5% 决策的可见前 4 名 total 完全相同）。统一期望得分 = 把「−10·向听」这类任意定标换成有物理意义的「期望得分」。

---

## 1. 函数形式（三因子，每项已定标；得分结构锚点来自三榜）

对候选弃牌 `tile`，打完后的局面 `s'`：

```
score(tile) = P_win(s')                    # 到胡概率（路线条件化 + 形质修正）
            × E_pay(r, s')                 # 胡时期望得分（含庄闲、财神上抬、连庄）
            − (1−P_win(s')) · P_opp(s') · E_loss(s')   # 未胡被自摸的期望赔付
            − feed_cost(tile, s')          # 喂牌的即时代价（量纲=分）
```

**得分结构锚点（我 18:20 三榜分析）**：前 32 名的单场分 = 「多胡（3–7 把）+ 平胡打底 + 连庄 ≥2 + 偶尔爆头/财飘」。
⇒ `E_pay` 的番数分布应**以平胡为底、连庄/爆头为上抬**，与我们「胡 4 把含爆头+财飘=419 分」同构。

| 因子 | 定标来源 | 关键修正 |
|---|---|---|
| `P_win(s')` | `routes.win_probability`（自对弈表 PAIR/MELD）× **形质修正**：`shape_value` 更好 ⇒ 同向听 P_win 更高（shape 族 +0.350 t3.19 是唯一家族级正结果） | **⚠ 自对弈表系统性偏高**（对手=自己；真机强 bot 胡率 29% vs 我们 20%）。缓释：门 2 按房配对核 `P_win` 偏差；偏差大则用 C 的真机数据重标。 |
| `E_pay(r,s')` | `routes.expected_pay` × `GOD_FAN_UPLIFT`（≥2 财神 ×1.25）× **连庄上抬**（当前未建模；三榜显示连庄是主要得分项） | 番数用实测 `PAIR_MEAN_FAN=1.68`/`MELD_MEAN_FAN=1.07` |
| `P_opp(s')` | `1 − lap_survival(assess(situation))` | **威胁被高估 1.5–1.9×**（C 01:38 / A 12:05）。用 GBDT（全库 0.95× 无偏）或 uplift 1.25→1.0。**抓打圈受限方无吃碰窗口**（A 18:32）⇒ 受限方 `P_ready` 应调低（不止 −0.05）。 |
| `E_loss(s')` | `routes.expected_loss`（庄闲 ×8 已含） | — |
| `feed_cost(tile,s')` | `visible_need(tile) × threat × (4−seen)/4` → **重定标为 `ΔP_opp × E_loss`**（见 §2） | `(4−seen)/4` 直接并入（④a 已实现 `feed_visibility`） |

**结构决定**：`score` 是得分期望（量纲=分），三因子都是概率或得分，乘/减有意义；不像「−10·向听」是为压过喂牌而拍的 10。

---

## 2. `feed_cost` 的量纲定标（把 97.25% 纠回有意义比例的核心）

`feed` 的本质 = 「这张牌让对手更快听牌/自摸」的**概率增量**。定标为：

```
feed_cost = ΔP_opp(tile) × E_loss(s')
```

其中 `ΔP_opp(tile)` = 「打出这张牌后，对手本圈自摸概率的增量」。`visible_need(tile)` 重新解释为「这张被吃碰后对手 `P_ready` 的条件增量」（先用归一化占位，待 C 的占用/序列模型线替换；C 的 recency 特征是文献做法，见 THREAD 18:40）。

**效果**：feed_cost 量纲 = 分，与 `P_win×E_pay` 直接可比 ⇒ **`feed_weight` 旋钮被消灭**（连 `shape-feed-low` 按错前提这类问题一起）。这是把「97.25% 由喂牌单键决定」纠回「有意义的权衡」的机制。

## 3. 预登记判据（机制门 + A/B 门，含 n 与 MDE）

**机制门**（不达标不进 A/B）：
- 门 1：`argmax(score)` 与全信息后见最优的一致率，显著高于同条件 `total` 基线（我 14:05 top-4 口径可复用）；
- 门 2：各分项 `E[预测]` 偏差**按房配对**可核对，**且** `P_win`/`P_opp` 回归斜率 ∈ **[0.8, 1.2]**（采纳 C 17:07 建议，防「均值对了方差压扁」——占用模型正是死在这：斜率 0.321）；
- 门 3（空干预防线）：`score` 在同向听并列候选上的**分辨率**（非全并列组占比）显著高于现状 40.5%（现状 59.5% 前 4 名并列）。

**A/B 门**：四座位旋转、同批种子、对照 v3；n=2 种子 ×120 场，灰区补第三种子。主指标名次分、次指标总得分/胡次数。**MDE 预登记**：名次分 ±0.10（≈1.5σ）。**采纳**：两种子同向且合并 t≥2.0。

## 4. 会让哪些臂变冗余（A 要的清单）

| 臂 | 落地后 |
|---|---|
| `shape-feed-low` / `feed-high` | **冗余**（feed_weight 被消灭） |
| `seen-feed` | **并入**（`(4−seen)/4` 成 feed_cost 一部分） |
| `seen-tiebreak` | **冗余**（并列由期望差自然打破） |
| `ukeire-order=blocks` | **冗余**（排序键被 score 取代） |
| `ukeire-wide/hand/early/deep` 族 | **部分冗余**（候选面问题由「先算进张再截断」评审 F3 单独解决） |
| `shape`/`shape-blocks`/`ukeire-hand` | **不冗余，是前身**——`shape_value` 作 `P_win` 形质修正的定标依据 |
| `risk-v3`（GBDT 对手模型） | **并入**（作 `P_opp` 源） |
| 序列模型 | **下游输入**（逐张占用喂给 feed_cost/P_opp；不阻塞本设计） |

**净效果**：一次落地可退役 6 个臂、并入 2 个在跑臂、把 shape 族从「孤立正结果」变成 `P_win` 形质修正的定标依据。

## 5. 风险与边界（诚实清单）

1. **⚠ 最大风险：`P_win` 表来自自对弈，非真机**（对手=自己 ⇒ 系统性偏高）。缓释：门 2 按房配对核偏差；偏差大则用 C 真机数据重标 `WIN_RATE_*`。**列为落地后第一个复核项。**
2. **量纲统一 ≠ 正确**：`ΔP_opp` 仍是估计（手写 `visible_need` 占位时尤其粗）。缓释：门 1 一致率 + 门 2 斜率区间。
3. **成本（19:05 已用 A 的真机实测更新）**：`score` 需 `ukeire`+`routes.evaluate`+`risk.assess`，对**每个候选**都算 ⇒ 高于现状「先截断再精算」。**但 A 从 709,205 条真机 `decision.made` 量出的预算余量比文档假设宽得多**：出牌相 p50 4.0ms / **p99 347ms / 最大 1381ms**，预算 1800ms，**263,129 条零超预算** ⇒ 可负担算力约现状 5 倍；碰吃相 p99 仅 3–4.5ms（近免费）。A 定的实现红线：**p99 ≤ 1000ms**，每候选期望计算须有**预筛**（候选面均值 2.8~10 张，不对全 34 张算）。另 A 18:32 的「超时自动胡」发现 ⇒ 真机超时后果是「能胡就自动胡」，贵模型上线的安全边际进一步变大。**结论：成本不是本设计的约束项**（原稿按文档 1800/600ms 写的保守估计作废）。
4. **我做不了的**：`src/**` 实现、单测、机制门执行、A/B 执行全归 A；本设计只交付「函数形式+定标+判据+冗余清单」。
5. **与 C 占用线关系**：占用/剩余张数作 `feed_cost`/`P_win` 的**输入**而非独立臂（与 A 17:05 合并裁决一致）；C 的 No-Go 证伪「静态特征替 V」，不阻塞本设计（占位用手写 `visible_need`）。

## 6. 给 A 的实现优先级（仅供排序）

1. `feed_cost` → `ΔP_opp × E_loss` 并接 `feed_visibility`（消灭 feed_weight）——单独成臂，最先测；
2. `−10·向听 + 形质` → `P_win × E_pay`（路线条件化 + 形质修正）——第二步；
3. 两步都过后 `total` 退役、`score` 接管。**分两步走不一把梭**：第一步掉分 ⇒ `ΔP_opp` 估计太粗，先补占用/对手模型。
